# Authentication Flow in PulseOps V1

## Overview
PulseOps V1 uses JWT (JSON Web Tokens) for stateless authentication, combined with refresh tokens for session management. The flow ensures secure, scalable authentication across the React frontend and Node.js/Express backend. Tokens are generated by the backend API and managed client-side with automatic expiry handling.

## Key Components
- **Frontend**: React app with AuthService and ApiClient services.
- **Backend**: Node.js/Express API with JWT generation, RBAC, and tenant isolation.
- **Token Storage**: localStorage (client-side; acceptable for SPAs but vulnerable to XSS).
- **Security Features**: Short-lived JWT (24h), refresh tokens (7d), server-side RBAC validation.

## Who Generates the Tokens?
The **backend API** (operationsmanager-api) generates tokens using the `jsonwebtoken` library. Secrets are loaded from environment variables (`JWT_SECRET`, `JWT_REFRESH_SECRET`). Tokens are created during login (`/api/auth/login`) and refresh (`/api/auth/refresh`) endpoints.

## Complete Step-by-Step Flow

### 1. User Enters Credentials
- **File**: `c:\My Development\Knowvana\pulseops_v1\src\shared\components\LoginForm.jsx`
- **Action**: User fills email/password, submits form.
- **Code**: `handleSubmit` prevents default, calls `await onLogin(email, password)` (line 32).

### 2. LoginForm Calls Parent Handler
- **File**: `LoginForm.jsx` → `onLogin` prop (passed from `App.jsx`).
- **File Called**: `c:\My Development\Knowvana\pulseops_v1\src\core\App.jsx` (`handleLogin` function).
- **Action**: `handleLogin` calls `await AuthService.login(email, password)`.

### 3. AuthService Initiates Login
- **File**: `c:\My Development\Knowvana\pulseops_v1\src\shared\services\authService.js`
- **Action**: `AuthService.login` validates inputs, calls `await ApiClient.post(urls.authLogin, { email, password })` (line 50).
- **Purpose**: Sends POST request to backend for authentication.

### 4. ApiClient Sends HTTP Request
- **File**: `c:\My Development\Knowvana\pulseops_v1\src\shared\services\apiClient.js`
- **Action**: `ApiClient.post` uses `fetch()` to POST to `http://localhost:4000/api/auth/login` (proxied via `vite.config.js`).
- **Headers**: Includes `Content-Type: application/json`.
- **Body**: `{ email, password }`.

### 5. Backend Validates and Generates Tokens
- **File**: `operationsmanager-api/src/core/routes/authRoutes.js` (handles `/api/auth/login`).
- **Action**:
  - Validates email/password against database (via `databaseService.js`).
  - If valid, generates JWT (`jwt.sign(payload, JWT_SECRET, { expiresIn: '24h' })`) and refresh token (`jwt.sign({ userId }, JWT_REFRESH_SECRET, { expiresIn: '7d' })`).
  - Returns JSON: `{ success: true, token: '<JWT>', refreshToken: '<refresh>', user: { id, name, email, role } }`.
- **Security**: Uses bcrypt for password hashing, RBAC checks user role.

### 6. Frontend Receives and Stores Tokens
- **File**: `apiClient.js` → `authService.js`
- **Action**: On success response, `AuthService` calls `ApiClient.setToken(token)` and `ApiClient.setRefreshToken(refreshToken)`.
- **Storage**: Tokens saved in `localStorage` (e.g., `localStorage.setItem('tokenKey', token)` using keys from `constants.json`).

### 7. AuthService Returns User Data
- **File**: `authService.js` → `App.jsx`
- **Action**: Returns user object; `handleLogin` sets `setUser(user)`, switches UI to `PlatformDashboard`.

### 8. Subsequent API Requests Include JWT
- **File**: `apiClient.js`
- **Action**: Every request attaches `Authorization: Bearer <JWT>` header.
- **Validation**: Backend verifies JWT on each request (e.g., in middleware `auth.js`).

### 9. Token Expiry and Refresh Handling
- **File**: `apiClient.js`
- **Action**: On 401 response, clears tokens, dispatches `'auth:session-expired'` event.
- **File**: `App.jsx` listens for event, resets to login.
- **Optional Refresh**: If refresh token exists, `ApiClient` can POST to `/api/auth/refresh` to get new JWT.

### 10. Logout Process
- **File**: UI → `AuthService.logout()` → `apiClient.js`
- **Action**: POST to `/api/auth/logout`, clears `localStorage`, dispatches event, resets `App.jsx` state.

## Security Assessment
- **Strengths**: Stateless JWT, short expiry, RBAC server-side, automatic cleanup on 401.
- **Weaknesses**: localStorage XSS risk (mitigate with CSP); no MFA; refresh logic optional.
- **Enterprise Recommendations**: Use httpOnly cookies for tokens, add MFA, audit logs, rate limiting.

## Files Involved
- Frontend: `LoginForm.jsx`, `App.jsx`, `authService.js`, `apiClient.js`, `constants.json`, `urls.json`
- Backend: `authRoutes.js`, `auth.js` (middleware), `databaseService.js`
- Config: `vite.config.js` (proxy), `.env.example` (vars)

This flow ensures secure, user-friendly authentication without server-side sessions.
